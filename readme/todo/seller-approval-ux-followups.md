# 판매자 승인(approval) flow 후속 작업

> 우선순위: 낮음 (가장 후순위). 세부 계획은 착수 시점에 수립.
> 배경: P2-1 판매자 승인 flow 구현 중 발견된 부가 UX 갭(1~3) + 추가로 필요성이 확인된 기능(4). 핵심 승인 로직(등록→대기→승인/반려→재제출)과 전역 로그아웃 버튼은 이미 구현됨.

## 1. 상단 로그인/로그아웃 버튼 + 개인 상태 영역
- 현재는 "로그아웃" 텍스트 버튼만 우측 상단에 존재.
- 로그인한 사용자의 이름/판매자명/role 등을 보여주는 상태 영역(아바타/드롭다운 등)으로 확장 검토.

## 2. 승인 대기 화면에 문의처 노출
- "승인 대기 중입니다" 안내에 문의 가능한 연락처(전화번호/이메일 등) 표시.
- 대기가 길어질 때 판매자가 문의할 수단이 현재 없음.

## 3. 반려 시나리오 보완
- 현재는 반려 사유 텍스트만 노출 + 재제출 폼. 반려 이력 확인, 반려 횟수 표시 등 추가 시나리오는 미정.
- 착수 시 실제 반려 운영 방식(관리자 쪽 운영 가이드 포함)을 함께 정할 것.

## 4. 관리자 직접 판매자 등록(계정 발급 포함)
- 배경: 사업 초기엔 셀프 가입이 아니라 **영업을 통해 서면 서류로 판매자를 받는 경우**가 있음. 이런 판매자는 가입→승인 대기 flow를 거칠 필요 없이 관리자가 계정과 업체 정보를 한 번에 만들어줘야 함.
- 요구사항(초안): 관리자 화면에서 판매자 이메일/기본정보 입력 → **계정 생성**(Supabase Admin API로 auth user 발급 필요, 초기 비밀번호/초대 방식은 착수 시 결정) + `admin_sellers` row를 **바로 `APPROVED` 상태로** 생성.
- 셀프 가입 승인 flow(현재 구현됨)와 별도 경로이므로, 기존 등록 mutation/화면과 얼마나 재사용할지는 착수 시 설계.
