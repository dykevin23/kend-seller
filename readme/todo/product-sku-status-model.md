# 상품 / SKU 상태 모델 + 구매자 노출 규칙 (kend 전달용)

> 2026-09-10 kend-seller에서 정리. `products.status` / `product_stock_keepings.status` 재정의.
> kend-seller 쪽 코드 반영 완료. **kend는 아래 §3 노출 규칙을 구현해야 함.**

---

## 배경

`products.status`와 `product_stock_keepings.status`는 같은 DB enum(`sales_status`: REGISTERED, PREPARE, SALE, SOLD_OUT, STOP, END)을 공유하는데, 각 레벨에서 무슨 의미인지가 정의된 적이 없었다. 실제로:

- 등록 시 SKU는 `PREPARE`로 명시 생성되는데 상품은 값을 안 넘겨 DB 기본값 `REGISTERED`에 멈춤 → kend가 `REGISTERED` 상품을 목록에서 제외하기 때문에 **신규 셀러 상품이 안 보이는 문제** 발생 (2026-09-08 coucou/SL0004 사례).

이번에 두 레벨의 상태 의미를 아래처럼 분리 정의했다.

---

## §1. 상품(product) 상태 — "판매자가 이 상품을 팔 의도가 있는가"

| 값 | 라벨 | 의미 | 진입 경로 | 구매자 탐색 노출 |
|---|---|---|---|---|
| `REGISTERED` | 등록 | **등록 미완료(임시저장)** — 현재는 이 경로로 진입하는 기능 없음. 향후 "임시저장" 기능용으로 예약 | (현재 없음) | ✗ |
| `PREPARE` | 준비중 | 등록은 끝났으나 판매 시작 전, **또는 판매하다가 판매자가 일시 중단** | 등록 완료 시 기본 진입 / SALE에서 되돌아옴 | ✗ |
| `SALE` | 판매중 | 정상 판매 중 | 판매자가 PREPARE/STOP에서 전환 | ○ (단, SKU 상태에 따라 구매가능 여부 다름) |
| `STOP` | 판매중지 | 판매자가 의도적으로 중단(단종 예정 등). PREPARE보다 재개 의사 낮은 뉘앙스 | 판매자 수동 | ✗ |
| `END` | 판매종료 | 영구 종료. 재판매 시 새 상품 등록 권장 | 판매자 수동 | ✗ |
| `SOLD_OUT` | 품절 | **상품 레벨에서는 사용하지 않음.** 품절은 SKU 단위 개념 → §3의 파생 규칙으로 표시 | — | — |

- **등록 완료 = 즉시 `PREPARE`.** `REGISTERED`는 실질적으로 미사용(미래 예약).
- kend-seller에서 판매자가 상태를 바꿀 때 고를 수 있는 값에서 `REGISTERED` 제외.

## §2. SKU(옵션) 상태 — "이 옵션 조합이 지금 주문 가능한가"

| 값 | 라벨 | 의미 |
|---|---|---|
| `PREPARE` | 준비중 | 등록 시 기본값. 또는 상품이 SALE인 도중에도 **이 옵션만** 판매자가 일시적으로 주문 중단(재입고 대기 등) |
| `SALE` | 판매중 | 정상 주문 가능 |
| `SOLD_OUT` | 품절 | 재고 0 도달 (자동/수동 모두 고려) |
| `STOP` | 판매중지 | 판매자가 이 옵션만 영구 중단(예: 이 색상 단종) |
| `REGISTERED` / `END` | — | SKU 레벨에서는 의미 없음. 사용하지 않음 |

- DB enum 값 자체는 6개 그대로(두 테이블이 공유). 사용 범위만 애플리케이션에서 제한.
- 상품 상태 일괄 변경이 더 이상 SKU 상태를 함께 덮어쓰지 않음(분리됨).

---

## §3. 구매자 노출 / 구매가능 규칙 — **kend 구현 대상**

### 핵심 원칙: "탐색"에서만 상태로 거르고, "참조"에서는 절대 사라지지 않는다

| 그룹 | 화면 | 규칙 |
|---|---|---|
| **탐색(discovery)** | 스토어 상품목록·카테고리, 검색결과, 홈 추천/베스트/신상품 | 아래 "탐색 노출 조건"을 만족할 때만 노출 |
| **참조(reference)** | 구매내역, 리뷰(내가 쓴 / 상품에 달린), 최근 본 상품, **찜(위시리스트)**, 장바구니, 문의내역, 반품·교환·AS | **상태와 무관하게 항상 노출.** 대신 구매 액션만 차단 (아래) |

### 탐색 노출 조건

상품이 탐색 화면에 뜨려면 **두 조건을 모두** 만족:
1. `product.status === 'SALE'`
2. 구매 가능한 SKU가 최소 1개 존재 — 즉 `sku.status === 'SALE' && sku.stock > 0` 인 SKU가 있음

→ `product.status === 'SALE'`인데 모든 SKU가 PREPARE/SOLD_OUT/STOP(또는 재고 0)이면 **탐색에서는 제외**. 단 상세페이지 자체는 살아있음(참조 그룹으로 들어오면 접근 가능, 리뷰·URL 보존).

### SKU 단위 구매가능 판정

특정 SKU를 주문할 수 있으려면 **전부** 만족:
```
product.status === 'SALE'  AND  sku.status === 'SALE'  AND  sku.stock > 0
```

### 참조 화면에서의 처리 (사라지지 않되 구매 차단)

- **상품 상세**: 진입은 되되, 구매 버튼 영역에 상태 배지 표시 + 구매 진행 차단.
- **상세페이지 옵션 선택**: 구매 불가 SKU(품절/중단)는 **숨기지 말고** 선택 불가(회색) 처리.
- **장바구니**: 항목은 유지하되, **해당 SKU 상태 기준으로**(상품 상태가 아니라) 체크박스 비활성화 + 별도 표기. 전체선택/주문금액 계산에서 제외.
- **구매내역·반품·교환·AS**: 상품 상태 변경과 **완전히 무관**. 이미 발생한 주문 이후 플로우는 영향받지 않음.

### 상태별 문구 (제안 — "구매불가"로 뭉치지 말 것)

| 상황 | 문구 예시 |
|---|---|
| 상품 SALE, SKU가 전부 재고 0 / SOLD_OUT | "일시 품절" (재입고 가능성 있음) |
| 상품 PREPARE | "판매 준비 중" |
| 상품/SKU STOP | "판매 중지된 상품입니다" |
| 상품 END | "판매 종료된 상품입니다" |
| 일부 옵션만 불가 | 해당 옵션에 "품절" / "판매중지" 표시, 나머지 옵션은 정상 |

## §4. kend-seller 쪽 반영 완료 항목 (참고)

- 등록 완료 시 `products.status`를 `PREPARE`로 명시 생성 (`createProduct`).
- 판매자 상품 상태 변경 UI에서 `REGISTERED` 선택지 제거.
- 상품 상태 일괄 변경이 SKU 상태를 함께 덮어쓰지 않도록 분리 (`updateProductsStatus`).
- 상태 상수 분리: `PRODUCT_STATUS_OPTIONS` / `SKU_STATUS_OPTIONS` (`app/features/products/constrants.ts`).

## §5. 아직 안 된 것 / 후속

- **기존에 `REGISTERED`로 멈춰 있는 상품 데이터** — 이번 수정은 신규 등록만 고침. 기존 행은 일괄 `PREPARE`로 올리는 마이그레이션이 필요한지 판단 필요(셀러가 의도적으로 준비중에 둔 게 아니라 버그로 묶인 것이므로 올려주는 게 맞을 듯).
- **SKU 단위 상태 변경 화면** — 재고관리 화면(B-2)에서 다룰 예정. 재고 0 → `SOLD_OUT` 자동 전환 주체도 그때 함께.
- kend가 §3 노출 규칙을 반영할 때, 현재 `status = 'REGISTERED'` 단순 제외 필터를 위 조건으로 교체.
